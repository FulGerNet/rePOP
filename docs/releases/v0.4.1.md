# reSOT v0.4.1

Windows demo and retail executables and the shared Android APK use version
0.4.1; Android versionCode is 11. Both targets still require the user's supported
Xbox game files. Game content, logs and compiled packages are not committed.

- **Retail flicker, black scenes and textures that stopped loading.** The
  retail ran the game up to 16 GPU submissions ahead of the executor, and the
  game reused memory those submissions still pointed to: vertex data was read
  as GPU commands, which made objects and textures flicker, turned whole
  scenes black (only the menus and overlays left) until the app restarted,
  or crashed. The retail now runs at most one submission ahead
  (`RESOT_KICK_AHEAD=16` restores the old behaviour). In the user's test of
  every retail map, the logs no longer show this.
- **Two Android crashes on the GPU thread** (seen in the dagger area): a
  visibility report sent to a misaligned address, and a texture palette
  outside the game's memory. Both are now rejected and logged instead.
- **Textures replaced by old render targets.** After a map change, a new
  texture placed where an old render target used to be could show that old
  image until the app restarted. The renderer now notices when the game has
  rewritten that memory and uses the texture.
- **Special Load Map crashes** (Windows, several maps in a row). After a load
  the Prince could keep the previous world's sector, and the next load
  crashed. The sector is now taken from the map's checkpoint when that
  happens. The user then loaded all 30 retail maps without a crash.
- **Loading screen that never ended** after many loads (about 30 maps and
  returns to the menu in one session). Each loading screen starts a new game
  thread; after 63 of them the game could no longer see that the thread had
  finished and waited forever. Fixed for the retail.
- **Android launcher: logs tip.** Shortly after the launcher opens, a small
  bubble beside the version shows "The game crashed? Tap here for logs!" for
  a few seconds. Tapping it, or the version, shares the logs as before.
- **Windows: hang diagnostics.** If the game stops sending work to the GPU for
  20 seconds, the log gets one dump of every thread's call chain
  (`RESOT_STALL_DUMP=0` turns it off).

Known, not fixed: for about a second on entering a level some surfaces can
show pink and green; objects can still flicker between black and visible
while the opening camera shows the map; some vertices, the Prince's too, can
be out of place for half a second (present since the project's start). The
loading-screen and render-target fixes were built but not yet checked in
game. The demo keeps 0.4.0's behaviour except the palette check.
See [VALIDATION.md](../VALIDATION.md) for commands and results.
